# M50.4 Supervisor Shell Hardening Runbook

Purpose:

- Keep M50 root POST shells safe under degraded persistence and hostile local
  request conditions before M51 adds shared contracts and store models.

## Expected Behavior

For `POST /workflows/:workflowId/dry-run`,
`POST /approvals/:approvalId/decision`, `POST /tasks`, and
`POST /tasks/:taskId/recover`:

- Store disabled or unavailable returns `store-unavailable`.
- Store-unavailable responses include no evidence or audit ids.
- Missing local-control token returns a guard error before route logic.
- Malicious Origin returns a guard error before route logic.
- Malicious Host returns a guard error before route logic.
- Responses never expose raw prompt, raw diff, raw patch, raw path, raw body, raw
  reason, raw action, URL, token, credential, session, raw log, raw trace, or raw
  database row content.

## Operator Checks

Before M51 or UI work uses these shells:

1. Run the M50.4 focused Supervisor tests.
2. Confirm the shell succeeds only when evidence/audit persistence is available.
3. Confirm task create and task recovery are still blocked until M51 store models.
4. Confirm new UI, CLI, or MCP surfaces do not persist local-control tokens.
5. Confirm no route calls an adapter directly.

## Stop Conditions

Stop the round if:

- A shell reports success while store persistence is unavailable.
- A shell returns evidence or audit ids that were not persisted.
- Guard failures leak private request payload data.
- A shell trusts request-body approval artifacts or execution authority.
- A shell starts any adapter, browser, Electron/CDP, GitHub, Codex App Server,
  account, or process boundary directly.

## Extending In M51

Use this order:

1. Add contracts for the shell DTOs and future task/account/client objects.
2. Add contract tests with forbidden raw field fixtures.
3. Add store-core repository interfaces.
4. Add SQLite migrations and round-trip tests.
5. Rewire Supervisor projections through the store while preserving M50.4 guard
   behavior.

## Closeout Gates

Every follow-up M50/M51 sub-round must run:

- Focused tests for touched packages.
- Focused build for touched packages.
- `pnpm scaffold:health`
- `pnpm audit:boundaries`
- `pnpm audit:sqlite-isolation`
- `pnpm audit:no-live-automation`
- `pnpm audit:skills`
- `pnpm verify:foundation`
- `git diff --check`
- clean `git status --short --branch`

## Rollback

If degraded-store or guard regressions appear, revert the M50.4 commit or
disable the affected shell before continuing. Do not allow shell success without
persisted evidence and audit traceability.

## Workflow Skills Used and Why

- `gsd-spec-driver`: keeps M50.4 shell hardening boundaries explicit.
- `gstack-delivery-workflow`: keeps the hardening round independently shippable.
- `superpowers-engineering-discipline`: keeps the round narrow and test-first.

## Project Skills Used and Why

- `codexhub-architecture-planner`: use for route and package boundary changes.
- `codexhub-contract-designer`: use before adding M51 schemas or DTOs.
- `codexhub-workflow-policy-reviewer`: use before any guard, approval, evidence,
  audit, or authority change.
- `codexhub-release-auditor`: use for every closeout.

## Skills Not Used by Default

- Browser Profile, Electron/CDP, Codex exec adapter, Playwright QA, deployment,
  telemetry, and external-agent skills are only required when a later sub-round
  touches those areas.
