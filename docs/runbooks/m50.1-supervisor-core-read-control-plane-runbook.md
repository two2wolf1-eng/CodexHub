# M50.1 Supervisor Core Read Control Plane Runbook

Purpose:

- Operate and extend the first M50 Supervisor read control-plane routes without
  opening live capability execution.

## Read Routes

M50.1 adds these root-level routes:

- `GET /capabilities`: M49.1 capability matrix projection.
- `GET /accounts`: degraded account pool placeholder until M51.
- `GET /clients`: degraded client pool placeholder until M51.
- `GET /tasks`: degraded task placeholder until M51.
- `GET /workflows`: workflow catalog and metadata-only run summaries.
- `GET /approvals`: approval inbox counts and evidence/audit ids.
- `GET /evidence`: evidence ref summaries.
- `GET /evidence/:id`: evidence ref detail summary.
- `GET /audit`: audit event summaries.
- `GET /audit/:id`: audit event detail summary.

## Operator Checks

Before relying on M50.1 routes:

1. Confirm `GET /health` returns `status: ok`.
2. Confirm `GET /capabilities` still classifies Browser and Electron as
   read-only, Git/Worktree/GitHub as dry-run, and Codex App Server/ChatGPT
   Business as missing real adapters.
3. Confirm `GET /accounts`, `GET /clients`, and `GET /tasks` still report
   `missing-contracts-store` until M51 lands.
4. Confirm evidence and audit responses do not contain raw prompt, body, path,
   action, target, reason, URL, token, cookie, session, MFA, or credential data.

## Stop Conditions

Stop the round if:

- A M50.1 read route calls a capability adapter directly.
- A read route starts a process, opens a network/browser/Electron boundary, or
  performs a local or remote write.
- A public response includes raw prompt, diff, patch, path, body, target, reason,
  action, URL, token, cookie, session, MFA, credential, raw log, raw trace, or
  raw database row content.
- Account, client, or task routes return invented records before M51 contracts
  and store models exist.

## Extending In M50.2

Use this order:

1. Add root-level POST mutation-shell tests first.
2. Reuse the existing global local-control token and trusted loopback Origin
   guard.
3. Add Host validation if not already covered by the route-gate layer.
4. Reject request-body approval artifacts and execution authority.
5. Persist only metadata-only evidence refs and audit ids.
6. Keep adapters out of route handlers.

## Closeout Gates

Every follow-up M50 sub-round must run:

- Focused Supervisor tests.
- Focused Supervisor build.
- `pnpm scaffold:health`
- `pnpm audit:boundaries`
- `pnpm audit:sqlite-isolation`
- `pnpm audit:no-live-automation`
- `pnpm audit:skills`
- `pnpm verify:foundation`
- `git diff --check`
- clean `git status --short --branch`

## Rollback

If M50.1 must be reverted, revert the M50.1 commit. It adds read routes, tests,
and docs only; it does not require a store migration or runtime cleanup.

## Workflow Skills Used and Why

- `gsd-spec-driver`: keeps M50.1 and M50.2 boundaries explicit.
- `gstack-delivery-workflow`: keeps the Supervisor API work independently
  shippable.
- `superpowers-engineering-discipline`: keeps read routes separate from future
  write surfaces.

## Project Skills Used and Why

- `codexhub-architecture-planner`: use for route/control-plane ownership.
- `codexhub-contract-designer`: use before changing M51 schemas or DTOs.
- `codexhub-workflow-policy-reviewer`: use before route gate, approval, evidence,
  or audit changes.
- `codexhub-release-auditor`: use for every M50 closeout.

## Skills Not Used by Default

- Browser Profile, Electron/CDP, Codex exec adapter, Playwright QA, deployment,
  telemetry, and external-agent skills are only required when a later sub-round
  touches those areas.
