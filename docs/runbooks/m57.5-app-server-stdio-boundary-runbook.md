# M57.5 App Server Stdio Boundary Runbook

Purpose:

- Verify and operate the governed stdio process boundary before M57 dispatch
  lifecycle wiring.

## Expected Behavior

The boundary should:

- Refuse to start unless dry-run id, approval artifact, ready preflight,
  approved approval status, passed canary, and compatible protocol drift are
  present.
- Return command hash, arg count, status, evidence refs, and audit ids only.
- Keep the returned transport non-enumerable in JSON output.
- Expose a stdio JSONL transport that can send initialize/initialized and later
  thread/turn/event messages.

## Operator Checks

1. Run `pnpm nx test codex-app-server-adapter`.
2. Run `pnpm nx build codex-app-server-adapter`.
3. Run `pnpm nx lint codex-app-server-adapter`.
4. Run `pnpm audit:no-live-automation`.
5. Confirm the process boundary allowlist points only to
   `packages/codex-app-server-adapter/src/stdio-process-boundary.ts`.
6. Confirm no raw command, args, prompt, diff, path, body, token, cookie,
   session, MFA, storage, account identifier, or process output body appears in
   public results.

## Stop Conditions

Stop if:

- The process starts without a completed M57 preflight.
- Drift is unknown/incompatible or live dispatch is blocked.
- Canary gate is not passed.
- Approval is missing or not approved.
- The transport object becomes JSON-serializable.
- Any command/file approval decision is silently accepted.

## M57.6 Entry Gate

M57.6 may begin after:

- Focused adapter test/build/lint pass.
- No-live automation audit passes.
- The boundary can be composed with `createCodexAppServerSessionController` using
  fake stdio in tests.

## Closeout Gates

- Focused tests/build/lint.
- Static audits.
- Independent M57.5 commit.
