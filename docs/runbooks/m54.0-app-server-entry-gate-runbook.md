# M54.0 Codex App Server Entry Gate Runbook

Purpose:

- Start M54 from a clean, verified foundation and keep real App Server dispatch
  behind contracts, store, policy, approval, evidence, and audit gates.

## Expected Behavior

The entry gate must:

- Confirm the repository is clean before M54 starts.
- Confirm `pnpm verify:foundation` passes.
- Record the current upstream App Server protocol source.
- Keep M54.0 documentation-only.
- Require M54.1 to define metadata-only contracts before any adapter or route
  implementation.

## Operator Checks

Before starting M54.1:

1. Confirm `git status --short` is clean after the M54.0 commit.
2. Review the upstream App Server README for protocol changes.
3. Confirm M54.1 only touches contracts, focused tests, and docs.
4. Confirm no App Server process launch, Codex Desktop CDP connection, browser
   connection, or profile storage read is added in M54.1.
5. Confirm all new contracts reject forbidden raw fields.

## Stop Conditions

Stop the round if:

- Any code reads token, cookie, session, MFA, credential, browser storage, raw
  prompt, raw diff, raw path, raw body, command body, or file body.
- Any Supervisor route calls an adapter directly.
- Any test bypasses workflow, policy, approval, evidence, or audit kernels to
  simulate a successful live write.
- Any Electron/CDP implementation uses `Runtime.evaluate`, DOM mutation,
  click/type, generic CDP passthrough, or network body capture.
- Any App Server protocol drift is unknown or incompatible and dispatch remains
  enabled.

## M54 Delivery Order

1. M54.1 contracts.
2. M54.2 metadata-only store tables.
3. M54.3 adapter package and JSONL transport.
4. M54.4 account and rate-limit read projections.
5. M54.5 thread, turn, and event mirror ingestion.
6. M54.6 approval bridge, drift detection, hardening, and full verify.

## Closeout Gates

Every M54 sub-round must run:

- Focused tests for touched packages.
- Focused build for touched packages.
- `pnpm scaffold:health`
- `pnpm audit:boundaries`
- `pnpm audit:sqlite-isolation`
- `pnpm audit:no-live-automation`
- `pnpm audit:skills`
- `git diff --check`

Run `pnpm verify:foundation` at M54 major-stage closeout.

## Rollback

If M54.0 documentation is wrong or incomplete, amend it before contracts start.
If later M54 code violates the entry gate boundaries, revert that later
sub-round commit and return to this entry gate.

## Workflow Skills Used and Why

- `gsd-spec-driver`: keeps M54 goals and stop conditions explicit.
- `gstack-delivery-workflow`: keeps each M54 sub-round independently shippable.
- `superpowers-engineering-discipline`: keeps the sequence small and
  evidence-based.

## Project Skills Used and Why

- `codexhub-architecture-planner`: use for package boundary sequencing.
- `codexhub-contract-designer`: use before changing shared schemas.
- `codexhub-workflow-policy-reviewer`: use before changing approval, evidence,
  audit, or policy behavior.
- `codexhub-codex-exec-adapter`: use before App Server transport or dispatch.
- `codexhub-electron-cdp-observer`: use before Electron/CDP observation.
- `codexhub-browser-profile-observer`: use before profile/browser observation.
- `codexhub-release-auditor`: use for every M54 closeout.

## Skills Not Used by Default

- `codexhub-playwright-qa`: only needed when Dashboard/browser QA behavior
  changes.
