# M51.3 Supervisor Metadata Projections Runbook

Purpose:

- Operate the M51 Supervisor account, client, and task projections as
  metadata-only read/control surfaces.

## Expected Behavior

Supervisor must:

- Return `/accounts`, `/clients`, and `/tasks` from M51 store repositories.
- Return only hashes, summaries, statuses, counts, evidence refs, and audit ids.
- Record task create shells as `CodexTaskIntent` and `CodexTaskRun` records.
- Record task recovery shells as `CodexRecoveryRun` records requiring human
  review.
- Keep live execution, external process starts, and adapter dispatch disabled.

## Operator Checks

Before enabling M52/M53 producers:

1. Run `pnpm nx test supervisor`.
2. Confirm `pnpm audit:boundaries` passes.
3. Confirm `pnpm audit:no-live-automation` passes.
4. Confirm no Supervisor route imports or calls a capability adapter directly.
5. Confirm private prompt/body/path fixtures do not appear in responses,
   evidence, audit, or M51 task/recovery records.

## Stop Conditions

Stop the round if:

- A Supervisor route calls a ChatGPT, browser, Electron, Codex App Server,
  GitHub, or account adapter directly.
- A response contains raw prompt, diff, path, body, token, cookie, session,
  MFA, credential, storage, raw log, or raw trace content.
- Task create starts a real Codex dispatch instead of recording metadata.
- Task recovery executes a real recovery step instead of recording a
  human-review shell.
- Local-control token, trusted Origin/Host, or forged-authority rejection
  behavior regresses.

## Extending In M52/M53

Use this order:

1. Let adapters/kernels create M51 records through governed store interfaces.
2. Keep Supervisor as a projection layer over store records.
3. Return hashes/refs/counts only from public routes.
4. Add focused leakage tests for each new producer.
5. Keep live admin, real profile connection, and Codex App Server dispatch
   disabled until a later approved milestone.

## Closeout Gates

Every follow-up M51-M53 sub-round must run:

- Focused tests for touched packages.
- Focused build for touched packages.
- `pnpm scaffold:health`
- `pnpm audit:boundaries`
- `pnpm audit:sqlite-isolation`
- `pnpm audit:no-live-automation`
- `pnpm audit:skills`
- `git diff --check`

Run `pnpm verify:foundation` at major-stage closeout.

## Rollback

If Supervisor projections leak raw private data or dispatch work directly,
revert the M51.3 commit and restore the M51.2 store-only baseline before
continuing.

## Workflow Skills Used and Why

- `gsd-spec-driver`: keeps route acceptance and hard boundaries explicit.
- `gstack-delivery-workflow`: keeps Supervisor projection work independently
  shippable.
- `superpowers-engineering-discipline`: keeps the round narrow, tested, and
  no-live.

## Project Skills Used and Why

- `codexhub-architecture-planner`: use for Supervisor/store boundaries.
- `codexhub-contract-designer`: use before changing projected record shapes.
- `codexhub-workflow-policy-reviewer`: use before changing POST guards,
  evidence, audit, approval, or forbidden-field behavior.
- `codexhub-release-auditor`: use for every closeout.

## Skills Not Used by Default

- Browser Profile, Electron/CDP, Codex exec adapter, Playwright QA, deployment,
  telemetry, and external-agent skills are only required when a later sub-round
  touches those areas.
