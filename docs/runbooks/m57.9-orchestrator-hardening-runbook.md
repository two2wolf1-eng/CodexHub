# M57.9 Orchestrator Hardening Runbook

Purpose:

- Provide the closeout checks for M57 before starting M58 diagnosis and recovery
  work.

## Expected State

After M57:

- Contracts describe task intent, run, preflight, approval, dispatch, event, and
  failure metadata.
- Store round-trips task intent/run/diagnosis/recovery metadata only.
- Orchestrator can prepare governed task dispatch preflight and lifecycle
  failure diagnosis.
- App Server process start is isolated to the governed adapter boundary.
- Supervisor `POST /tasks` records orchestrator preflight metadata but does not
  call adapters directly.

## Operator Checks

1. Confirm `git status --short` is empty before hardening.
2. Run `pnpm scaffold:health`.
3. Run `pnpm audit:boundaries`.
4. Run `pnpm audit:sqlite-isolation`.
5. Run `pnpm audit:no-live-automation`.
6. Run `pnpm audit:skills`.
7. Run `pnpm verify:foundation`.
8. Confirm no App Server process was started by tests.

## Stop Conditions

Stop before M58 if:

- Full foundation verification fails.
- Any route calls an adapter directly.
- A live process starts without the M57.5 governed boundary.
- Any result stores raw prompt, diff, path, body, token, cookie, session, MFA,
  storage, or request-body approval artifacts.
- `POST /tasks` marks request-body approval as approved authority.

## M58 Entry Gate

M58 may begin after:

- M57.9 hardening docs are committed.
- `verify:foundation` passes.
- Worktree is clean.

## Closeout Gates

- Full foundation verification.
- Independent M57.9 commit.
- Clean git state after commit.
