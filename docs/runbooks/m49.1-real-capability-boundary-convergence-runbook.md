# M49.1 Real Capability Boundary Convergence Runbook

Purpose:

- Give future Codex rounds a safe entry point from the M49 planning queue into
  M50 Supervisor control-plane implementation.

## Before Starting M50

1. Read `docs/real-capability-matrix.md`.
2. Read `docs/security-boundaries.md`.
3. Confirm the M49-M60 backlog still points to M50 as the next implementation
   stage.
4. Confirm `pnpm scaffold:health`, audits, and foundation verification pass.
5. Confirm no M49.1 document is used as permission to bypass child approvals.

## M50 Work Split

Use this order:

1. M50.1 core read routes and metadata-only projections.
2. M50.2 local-control token, trusted Origin, Host, and request-body authority gates.
3. M50.3 mutation shells for workflow dry-run, approval decision, task create,
   and task recovery planning.
4. M50.4 store-backed degraded states and evidence/audit read projections.
5. M50.5 route drift tests, no-direct-adapter-execute checks, release/review/runbook closeout.

## Operator Stop Conditions

Stop the round if:

- A Supervisor route imports or calls an adapter execute function directly.
- A POST route accepts request-body approval artifacts or execution authority.
- A public response contains token, cookie, session, MFA, raw prompt, raw diff,
  raw path, raw body, raw URL, raw trace, raw log, or raw database row content.
- A route crosses a live process, network, browser, Electron, GitHub, or account
  boundary.
- A high/critical action can proceed without store-resolved approval.

## Closeout Gates

Every M50 sub-round must run:

- Focused tests for touched Supervisor routes and helper kernels.
- Focused lint/build for touched projects.
- `pnpm scaffold:health`
- `pnpm audit:boundaries`
- `pnpm audit:sqlite-isolation`
- `pnpm audit:no-live-automation`
- `pnpm audit:skills`
- `pnpm verify:foundation`
- `git diff --check`
- clean `git status --short --branch`

## Rollback

If M49.1 registration is wrong, revert the M49.1 commit. It adds only docs and
config registration and does not require store migration or runtime cleanup.

## Workflow Skills Used and Why

- `gsd-spec-driver`: keeps M50 entry tasks scoped.
- `gstack-delivery-workflow`: keeps M50 split into independently shippable rounds.
- `superpowers-engineering-discipline`: prevents one-shot control-plane expansion.

## Project Skills Used and Why

- `codexhub-architecture-planner`: use for M50 route/control-plane ownership.
- `codexhub-contract-designer`: use before adding M51 schemas or DTOs.
- `codexhub-workflow-policy-reviewer`: use before route gate or approval changes.
- `codexhub-release-auditor`: use for every M50 closeout.

## Skills Not Used by Default

- Browser Profile, Electron/CDP, Codex exec, policy backend, telemetry exporter,
  deployment, external agent, and Playwright QA skills are only required when a
  later sub-round touches those areas.
