# M51.1 Unified Metadata Contracts Runbook

Purpose:

- Use the M51 contracts as the only shared language for upcoming account,
  client, task, quota, evidence, checkpoint, and recovery metadata records.

## Expected Behavior

M51 metadata contract producers must:

- Store ids, hashes, summaries, statuses, counts, timestamps, evidence refs,
  audit ids, and explicit boundary booleans only.
- Reject raw prompt, diff, path, body, token, cookie, session, MFA, credential,
  password/passkey, browser storage, raw logs, and raw traces.
- Keep live execution disabled unless a later governed round explicitly adds an
  approval/evidence/audit path.
- Produce summaries that are sanitized before persistence or public projection.

## Operator Checks

Before using these records in store or Supervisor:

1. Run the contracts test/build.
2. Confirm scaffold health lists every new public schema.
3. Confirm new persistence tests use the exact schemas rather than ad hoc JSON.
4. Confirm no UI, CLI, MCP, Supervisor route, or adapter bypasses contracts.
5. Confirm producers hash or summarize private inputs before record creation.

## Stop Conditions

Stop the round if:

- A new record accepts raw prompt, path, body, token, cookie, session, MFA,
  credential, or browser storage fields.
- A public response includes raw private input instead of a hash or summary.
- A route calls an adapter directly.
- A test or fixture bypasses workflow/security kernels for a write operation.
- Browser profile work attempts to read cookie, token, session, storage, or MFA
  material.

## Extending In M51.2

Use this order:

1. Add `store-core` repository interfaces for the M51 records.
2. Add SQLite tables with the existing payload JSON pattern.
3. Add focused round-trip tests for each repository.
4. Add negative tests that prove forbidden fields are rejected before storage.
5. Only then rewire Supervisor projections in M51.3.

## Closeout Gates

Every follow-up M51-M53 sub-round must run:

- Focused tests for touched packages.
- Focused build for touched packages.
- `pnpm scaffold:health`
- `pnpm audit:boundaries`
- `pnpm audit:sqlite-isolation`
- `pnpm audit:no-live-automation`
- `pnpm audit:skills`
- `git diff --check`

Run `pnpm verify:foundation` at major-stage closeout.

## Rollback

If a forbidden raw field reaches a contract, revert the M51.1 commit and restore
the M50.4 missing-contract/store blocker. Do not add store persistence or
Supervisor route projections until the contract suite passes again.

- `codexhub-architecture-planner`: use for package boundary checks.
- `codexhub-contract-designer`: use before changing M51 schemas.
- `codexhub-workflow-policy-reviewer`: use before changing evidence, audit,
  approval, or forbidden-field behavior.

## Skills Not Used by Default

- Browser Profile, Electron/CDP, Codex exec adapter, Playwright QA, deployment,
  telemetry, and external-agent skills are only required when a later sub-round
  touches those areas.
