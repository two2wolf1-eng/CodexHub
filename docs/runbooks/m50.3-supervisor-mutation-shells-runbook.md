# M50.3 Supervisor Mutation Shells Runbook

Purpose:

- Operate the first root-level Supervisor POST shells without enabling live
  workflow, task, account, Browser, Electron, Codex App Server, ChatGPT
  Business, GitHub, or external process execution.

## Shell Behavior

Available shells:

- `POST /workflows/:workflowId/dry-run`
- `POST /approvals/:approvalId/decision`
- `POST /tasks`
- `POST /tasks/:taskId/recover`

All shells:

- Require trusted loopback Host and trusted Origin through the shared M50.2
  guard.
- Require the local-control header and configured local-control key.
- Reject request-body `authority`, `approvalArtifact`, and execution authority
  payloads.
- Return only ids, hashes, statuses, summaries, evidence refs, audit ids, and
  boundary booleans.
- Create metadata-only evidence and audit records when the store is available.
- Never call adapters directly.

Task shells:

- `POST /tasks` returns `missing-contracts-store` until M51 task contracts and
  repositories exist.
- `POST /tasks/:taskId/recover` returns `missing-contracts-store` until M51 task
  and recovery contracts exist.

## Operator Checks

Before exposing a new shell to UI, CLI, or MCP:

1. Confirm the shell is already protected by the shared POST guard.
2. Confirm hostile request-body authority is rejected.
3. Confirm shell output has no raw prompt, raw diff, raw patch, raw path, raw
   body, raw reason, raw action, URL, token, credential, session, or raw log.
4. Confirm accepted shells create evidence refs and audit ids before success is
   returned.
5. Confirm adapters are invoked only through future workflow/security kernels,
   not from the route.

## Stop Conditions

Stop the round if:

- A POST shell succeeds without evidence or audit refs while a store is
  available.
- A POST shell trusts request-body approval artifacts or execution authority.
- A route starts a process, browser, Electron/CDP connection, GitHub network
  call, Codex App Server process, or account operation directly.
- A route returns or persists raw prompt, diff, patch, path, body, action, reason,
  target, URL, token, credential, session, raw trace, raw log, or raw database
  row content.
- Task create or recovery mutates task state before M51 contracts and store
  models exist.

## Extending In M51

Use this order:

1. Add shared contracts under `packages/contracts`.
2. Add store-core async repository interfaces.
3. Add SQLite repositories and idempotent migrations in `packages/store-sqlite`.
4. Add Supervisor projections against those repositories.
5. Keep all live adapters disabled until policy, approval, evidence, and audit
   paths are implemented.

## Closeout Gates

Every follow-up M50/M51 sub-round must run:

- Focused tests for touched packages.
- Focused build for touched packages.
- `pnpm scaffold:health`
- `pnpm audit:boundaries`
- `pnpm audit:sqlite-isolation`
- `pnpm audit:no-live-automation`
- `pnpm audit:skills`
- `pnpm verify:foundation`
- `git diff --check`
- clean `git status --short --branch`

## Rollback

If a shell violates the metadata-only or authority boundary, revert the M50.3
commit or disable the affected route before continuing. Do not patch around the
issue by trusting request-body authority or skipping evidence/audit trace
creation.

## Workflow Skills Used and Why

- `gsd-spec-driver`: keeps M50.3 mutation-shell boundaries explicit.
- `gstack-delivery-workflow`: keeps the shell round independently shippable.
- `superpowers-engineering-discipline`: prevents task, adapter, or live execution
  scope creep.

## Project Skills Used and Why

- `codexhub-architecture-planner`: use for Supervisor route ownership and M51
  package boundary planning.
- `codexhub-contract-designer`: use before adding M51 shared schemas or DTOs.
- `codexhub-workflow-policy-reviewer`: use before any route gate, approval,
  evidence, audit, or authority change.
- `codexhub-release-auditor`: use for every M50/M51 closeout.

## Skills Not Used by Default

- Browser Profile, Electron/CDP, Codex exec adapter, Playwright QA, deployment,
  telemetry, and external-agent skills are only required when a later sub-round
  touches those areas.
