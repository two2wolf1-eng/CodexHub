# M50.2 Supervisor Route Gate Hardening Runbook

Purpose:

- Keep Supervisor POST and OPTIONS requests local-control only while future M50
  mutation shells are added.

## Guard Behavior

For POST and OPTIONS:

- Host must be loopback or explicitly configured as trusted.
- Origin, when present, must be trusted loopback or explicitly configured.
- POST requires the local-control header to match the configured local-control
  key.
- OPTIONS requires the local-control header name in
  `access-control-request-headers`.
- Request-body approval artifacts and execution authority are never trusted by
  route handlers.

For GET:

- M50.1 read routes remain available without local-control token checks.
- Origin validation still rejects untrusted browser origins when an Origin header
  is present.

## Operator Checks

Before adding a new POST route:

1. Add a test for malicious Origin rejection.
2. Add a test for untrusted Host rejection.
3. Add a test for missing and invalid local-control token rejection.
4. Add a test for trusted loopback Host and Origin acceptance.
5. Add a test that request-body approval artifacts and authority objects are
   rejected or ignored.
6. Confirm response data remains ids, hashes, statuses, summaries, evidence refs,
   audit ids, counts, and boundary booleans only.

## Stop Conditions

Stop the round if:

- A route bypasses the shared guard.
- A route accepts request-body approval artifacts as authority.
- A route starts an adapter, process, network, browser, Electron, GitHub, or
  account boundary directly.
- A route returns raw prompt, diff, patch, path, body, target, reason, action,
  URL, token, credential, raw log, raw trace, or raw database row content.
- A non-loopback Host is trusted without explicit review and registration.

## Extending In M50.3

Use this order:

1. Add tests for root-level mutation shells.
2. Add minimal shell responses.
3. Use store-backed approval/evidence/audit paths.
4. Keep adapters outside route handlers.
5. Keep all shells dry-run or approval-decision only until M51 contracts exist.

## Closeout Gates

Every follow-up M50 sub-round must run:

- Focused Supervisor tests.
- Focused Supervisor build.
- `pnpm scaffold:health`
- `pnpm audit:boundaries`
- `pnpm audit:sqlite-isolation`
- `pnpm audit:no-live-automation`
- `pnpm audit:skills`
- `pnpm verify:foundation`
- `git diff --check`
- clean `git status --short --branch`

## Rollback

If the M50.2 guard blocks a required local integration, add an explicit trusted
Host through reviewed configuration or revert the M50.2 commit. Do not widen Host
matching to remote or wildcard values.

## Workflow Skills Used and Why

- `gstack-delivery-workflow`: keeps the guard hardening independently shippable.
- `superpowers-engineering-discipline`: prevents mutation or adapter scope creep.

## Project Skills Used and Why

- `codexhub-architecture-planner`: use for Supervisor guard ownership.
- `codexhub-contract-designer`: use before changing M51 schemas or DTOs.
- `codexhub-workflow-policy-reviewer`: use before any route gate, approval,
  evidence, or audit change.
- `codexhub-release-auditor`: use for every M50 closeout.

## Skills Not Used by Default

- Browser Profile, Electron/CDP, Codex exec adapter, Playwright QA, deployment,
  telemetry, and external-agent skills are only required when a later sub-round
  touches those areas.
