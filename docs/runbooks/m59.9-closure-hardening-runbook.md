# M59.9 Closure Hardening Runbook

Purpose:

- Provide the operating handoff from M59 closure to M60 production readiness.

## Operator Checks

1. Use `GET /tasks/closures` to inspect closure projection counts.
2. Use `POST /tasks/:taskId/closure` only with metadata fields.
3. Treat GitHub branch publish and draft PR fields as dry-run plan hashes.
4. Treat CI status as a mirror, not a live provider authority.
5. Require future live task expansion to pass M60 readiness, drift, canary, and
   audit gates.

## Stop Conditions

Stop if:

- Any closure route stores raw prompt, diff, path, body, token, cookie, session,
  MFA, storage, or local-control token.
- Supervisor starts direct adapter execution from a route.
- GitHub closure creates branch publish or draft PR runs without explicit child
  approval.
- CI mirror starts polling or executing a provider outside its own governed
  control plane.

## M60 Handoff

M60 should establish protocol drift gates, desktop drift gates, canary tasks,
live smoke approval, production readiness, recovery playbooks, and metadata-only
audit export before high-risk live task expansion.

## Workflow Skills Used and Why

- `gsd-spec-driver`: records stage acceptance and M60 handoff.
- `gstack-delivery-workflow`: records release closure.
- `superpowers-engineering-discipline`: keeps closure evidence-based.

## Project Skills Used and Why

- `codexhub-release-auditor`: records verification checks.
- `codexhub-workflow-policy-reviewer`: documents stop conditions.

## Skills Not Used by Default

- Contract, Electron/CDP, browser profile, and Playwright QA skills are only
  needed when those surfaces change.
