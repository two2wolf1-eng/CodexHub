# M59.7 GitHub Closure Dry-Run Handoff Runbook

Purpose:

- Provide operating checks for handing a task closure to GitHub dry-run control
  planes.

## Operator Checks

1. Create branch publish and draft PR dry-runs from metadata-only task closure
   evidence.
2. Create approval requests when needed, but do not treat requested approval as
   execution authority.
3. Link only dry-run plan hashes into `POST /tasks/:taskId/closure`.
4. Confirm closure reports `waiting_approval` until approved child runs exist.
5. Confirm branch publish, draft PR, and chain run counts remain zero during
   dry-run handoff.

## Stop Conditions

Stop if:

- A closure handoff creates a GitHub child run automatically.
- A dry-run response exposes owner, repo, branch name, file path, commit text,
  PR body text, token, cookie, session, MFA, storage, or local-control token.
- `liveRemoteWriteAllowed`, `pushAllowed`, `mergeAllowed`, or
  `networkBoundaryInvoked` becomes true during dry-run handoff.
- A new source kind is introduced without a contracts round.
