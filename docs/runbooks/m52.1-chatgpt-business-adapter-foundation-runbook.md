# M52.1 ChatGPT Business Adapter Foundation Runbook

Purpose:

- Operate the ChatGPT Business adapter foundation as a fixture-first,
  metadata-only producer for M51 workspace, membership, account binding, and
  quota records.

## Expected Behavior

The adapter must:

- Export only public package entrypoints.
- Keep manifest and read plans read-only by default.
- Mirror fixture members into M51 metadata records.
- Isolate individual fixture failures and block when every member fails.
- Return workspace identity and quota data as hashes/counts only.
- Keep invite/remove/replace admin helpers dry-run blocked.

## Operator Checks

Before wiring M52 into Supervisor/store:

1. Run `pnpm nx test chatgpt-business-adapter`.
2. Confirm `pnpm audit:boundaries` passes.
3. Confirm `pnpm audit:no-live-automation` passes.
4. Confirm no HTTP client, browser connector, external process runner, or live
   admin executor exists in the package.
5. Confirm private fixture values do not appear in serialized adapter outputs.

## Stop Conditions

Stop the round if:

- The adapter reads browser storage, credentials, tokens, cookies, sessions,
  MFA state, or raw profile paths.
- A public output contains raw workspace/member/email/display/reset values.
- Invite/remove/replace starts a real admin operation.
- A package imports another package internal `src` path.
- Supervisor or UI calls the adapter directly instead of future governed
  workflow/store paths.

## Extending Later

Use this order:

1. Add real adapter readiness as metadata-only and disabled by default.
2. Persist adapter outputs through M51 store repositories.
3. Project persisted records through Supervisor, not direct adapter calls.
4. Add approval artifacts before any live admin plan can move beyond blocked.
5. Keep live admin disabled until a later approved milestone.

## Closeout Gates

Every follow-up M52/M53 sub-round must run:

- Focused tests for touched packages.
- Focused build for touched packages.
- `pnpm scaffold:health`
- `pnpm audit:boundaries`
- `pnpm audit:sqlite-isolation`
- `pnpm audit:no-live-automation`
- `pnpm audit:skills`
- `git diff --check`

Run `pnpm verify:foundation` at major-stage closeout.

## Rollback

If the adapter leaks raw private data or introduces a live admin path, revert
the M52.1 commit and restore the M51.3 Supervisor metadata baseline.

## Workflow Skills Used and Why

- `gsd-spec-driver`: keeps adapter acceptance and hard boundaries explicit.
- `gstack-delivery-workflow`: keeps the adapter foundation independently
  shippable.
- `superpowers-engineering-discipline`: keeps the round narrow, tested, and
  no-live.

## Project Skills Used and Why

- `codexhub-architecture-planner`: use for package and import boundaries.
- `codexhub-contract-designer`: use before changing M51 output record shapes.
- `codexhub-workflow-policy-reviewer`: use before changing admin, approval,
  evidence, audit, or forbidden-field behavior.
- `codexhub-release-auditor`: use for every closeout.

## Skills Not Used by Default

- Browser Profile, Electron/CDP, Codex exec adapter, Playwright QA, deployment,
  telemetry, and external-agent skills are only required when a later sub-round
  touches those areas.
