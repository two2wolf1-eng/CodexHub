# M45.10 Final Deep Governance Baseline Runbook

## Purpose

Use this runbook before starting M46+ work. It summarizes the expected clean baseline after the ten M45 debug rounds.

## Preconditions

- The branch starts from a clean worktree.
- Product defaults remain conservative and disabled unless a future round explicitly changes them.
- Capability providers remain non-authoritative.
- Real live smoke is not run unless a future round defines dry-run, approval, evidence, and audit for that exact path.

## Operator Checklist

1. Confirm the current branch is clean.
2. Review `docs/reviews/m0-m45-capability-governance-matrix.md`.
3. Confirm the next round has a bounded GSD spec, non-scope, affected projects, risk level, and acceptance criteria.
4. Run the foundation gate set before adding new live capability.
5. Add tests before widening any route, adapter boundary, store record, Dashboard mutation panel, CLI mutation command, or MCP write surface.

## Foundation Gate Set

- `pnpm scaffold:health`
- `pnpm audit:boundaries`
- `pnpm audit:sqlite-isolation`
- `pnpm audit:no-live-automation`
- `pnpm audit:skills`
- `pnpm verify:foundation`
- `git diff --check`
- clean `git status --short --branch`

## Rollback Notes

- If final registration drifts, revert the M45.10 commit and reapply only the missing docs/tooling registration.
- If a future round fails due to a M45.10 scaffold-health requirement, verify the documented file exists before loosening the check.
- Do not bypass a failing governance audit by broadening an allowlist unless the round includes a review document explaining why the new boundary is safe.
