# M56.1 Scheduler Contracts Runbook

Purpose:

- Provide shared scheduler readiness language before runtime scoring and leases
  are introduced.

## Expected Behavior

Contracts must:

- Represent account readiness with `account_ready`, `quota_depleted`,
  `wrong_account`, `workspace_mismatch`, `removed`, `pending`, or `unknown`.
- Represent client readiness with `client_ready`, M55 diagnosis hints, removed,
  pending, or unknown states.
- Store only ids, hashes, statuses, scores, counts, evidence refs, audit ids,
  and short summaries.
- Reject raw or unmodeled metadata.

## Operator Checks

Before M56.2:

1. Run `pnpm nx test contracts`.
2. Run `pnpm nx build contracts`.
3. Run `pnpm nx lint contracts`.
4. Confirm scheduler projections do not contain raw task text, raw paths, or
   raw account/profile data.
5. Confirm `dispatchAllowed` is only metadata and does not invoke an adapter.

## Stop Conditions

Stop if:

- A scheduler schema accepts raw prompt, diff, path, body, token, cookie,
  session, MFA, storage, profile path, command line, or network body data.
- A Scheduler contract grants authority without policy, approval, evidence, and
  audit.
- A route, UI, or test calls an adapter directly while bypassing governance.

## Extending Later

Use this order:

1. M56.2 adds scheduler kernel scoring using these statuses.
2. M56.3 adds lease bundle handling.
3. M56.4 projects scheduler-ready metadata through Supervisor.
4. M56.5 runs concurrency rehearsal and full verification.
5. M57 uses the same preflight language before real App Server dispatch.
