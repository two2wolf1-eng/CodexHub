# M56.3 Scheduler Lease Bundle Runbook

Purpose:

- Create scheduler lease metadata for account, client, profile, thread, worktree,
  task, and quota targets without storing raw target keys or lease secrets.

## Expected Behavior

Lease helpers must:

- Hash target keys and holder keys.
- Set `leaseSecretStored` to `false`.
- Treat existing active/requested leases from another holder as conflicts.
- Emit blocked preflight checks for conflicts.
- Leave existing leases untouched.

## Operator Checks

Before M56.4:

1. Run `pnpm nx test codex-scheduler-kernel`.
2. Run `pnpm nx build codex-scheduler-kernel`.
3. Run `pnpm nx lint codex-scheduler-kernel`.
4. Confirm serialized lease bundles do not include raw worktree/profile paths,
   account names, holder keys, or lease secrets.
5. Confirm conflict checks are metadata only and do not release existing leases.

## Stop Conditions

Stop if:

- A lease stores a raw path, raw account identifier, holder key, or secret.
- A helper mutates store state or releases an existing lease.
- A helper calls App Server, browser, Electron, OS process, or filesystem write
  capabilities.

## Extending Later

Use this order:

1. M56.4 projects scored account/client/task metadata through Supervisor.
2. M56.5 runs concurrent scheduling rehearsal and full verification.
3. M57 uses lease bundle checks before real dispatch.
4. Later persistent lease storage adds expiration/release governance.
