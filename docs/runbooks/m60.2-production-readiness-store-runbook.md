# M60.2 Production Readiness Store Runbook

Purpose:

- Persist production readiness canary, drift, readiness, and audit export
  records as metadata-only SQLite projections.

## Operator Checks

1. Confirm all M60 records are written through store repositories, not raw SQL
   outside `store-sqlite`.
2. Confirm canary records contain only task hashes, status, counts, evidence
   refs, and audit ids.
3. Confirm drift records contain only baseline/observed hashes and drift
   counts.
4. Confirm audit export summaries contain only manifest/export hashes and
   counts.
5. Confirm readiness gates link canary/drift/audit metadata and do not grant
   execution authority.

## Stop Conditions

Stop if:

- Any M60 store record contains raw prompt, diff, path, body, token, cookie,
  session, MFA, storage, raw schema, raw target, raw canary output, or raw audit
  record data.
- SQLite bindings appear outside `packages/store-sqlite`.
- A readiness record is treated as direct permission to run live automation.

## Recovery

- Remove the unsafe projection before any downstream route or kernel reads it.
- Recreate the record from hash/count/status metadata only.
- Re-run the focused store test and static audits before continuing.

## Next Round

M60.3 should add production readiness kernel helpers that derive canary, drift,
readiness, and audit projections without reading raw private payloads.
