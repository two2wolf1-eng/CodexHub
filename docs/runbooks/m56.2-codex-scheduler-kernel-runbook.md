# M56.2 Codex Scheduler Kernel Runbook

Purpose:

- Score Codex accounts and clients using existing metadata-only contracts.

## Expected Behavior

The scheduler kernel must:

- Classify ready accounts as `account_ready`.
- Classify quota exhaustion, wrong account, workspace mismatch, removed, and
  pending states without raw account data.
- Classify clients as ready, frozen, App Server unresponsive, logged out,
  removed, pending, or unknown using M55 health metadata.
- Produce account/client pools with entry hashes, scores, counts, and block
  reasons only.

## Operator Checks

Before M56.3:

1. Run `pnpm nx test codex-scheduler-kernel`.
2. Run `pnpm nx build codex-scheduler-kernel`.
3. Run `pnpm nx lint codex-scheduler-kernel`.
4. Confirm no scheduler helper calls an adapter or enumerates local processes.
5. Confirm pool outputs do not include raw pool keys, account identifiers, client
   paths, profile paths, or task text.

## Stop Conditions

Stop if:

- Scoring reads tokens, cookies, sessions, MFA, profile storage, browser
  storage, network body, command line, prompt, diff, or raw filesystem paths.
- A scoring result grants execution authority.
- A test bypasses governance by directly dispatching through an adapter.

## Extending Later

Use this order:

1. M56.3 adds lease bundle and conflict checks.
2. M56.4 projects scored metadata through Supervisor.
3. M56.5 runs concurrent scheduling rehearsal and full verification.
4. M57 consumes scheduler preflight before App Server dispatch.
