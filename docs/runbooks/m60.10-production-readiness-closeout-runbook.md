# M60.10 Production Readiness Closeout Runbook

Purpose:

- Hand off M60 as the production readiness baseline for future live task work.

## Baseline Checks

1. Confirm M60.1 through M60.9 commits are present.
2. Confirm `pnpm verify:foundation` has passed after the M60 E2E rehearsal.
3. Run static closeout audits.
4. Confirm no live external probe or adapter expansion was added during
   closeout.
5. Commit the final closeout docs.

## Operating Expectations

- Readiness must be created before high-risk live task dispatch is considered.
- Incompatible or unknown drift blocks high-risk live task readiness.
- Canary failure blocks high-risk live task readiness.
- Live smoke requires approval metadata and remains non-executing until a future
  approved runner is implemented.
- Audit export returns metadata summaries only.

## Stop Conditions

Stop if:

- A production readiness route calls an adapter directly.
- Live smoke executes a real process or network probe without a separate
  approved implementation round.
- Drift or canary blockers can be bypassed for high-risk live tasks.
- Any persisted output contains raw prompt, diff, path, body, schema, target,
  audit record, canary output, token, cookie, session, MFA, or storage.

## Handoff

The next stage can build on:

- Production readiness contracts and store repositories.
- Production readiness kernel bundle helpers.
- Supervisor projections for readiness, canary, drift, and audit summaries.
- Approval-gated live-smoke shell.
- M60 E2E rehearsal and foundation verification evidence.

The next stage should not assume:

- A real live smoke runner exists.
- GitHub publish or draft PR creation is live.
- Desktop or App Server drift checks can bypass review.
- Any account, profile, credential, or session material can be read or stored.
