# 0011 GitHub Provider

Status: M19 governed PR lifecycle observation, read-only UX, rehearsal, and hardening.

CodexHub integrates GitHub as the first remote provider through a governed adapter. The provider is disabled by default and now supports metadata-only planning, an approval-gated read-only metadata HTTP control plane, Dashboard/CLI read-only views, draft PR readiness planning, an approval-gated existing-branch draft PR creation control plane, read-only Draft PR run projection, fixture-only Draft PR acceptance rehearsal, M17 governed new-branch publish planning/control-plane/read-only UX, and M18 publish-to-draft-PR chain projection.

Boundary rules:

- Token source: `CODEXHUB_GITHUB_TOKEN`.
- Token output: configured/missing plus hash only; never the token value.
- Allowed host: `api.github.com`.
- Product default: disabled.
- M15b runtime enablement: `CODEXHUB_GITHUB_PROVIDER_ENABLED=true`.
- M15b HTTP boundary: exactly one audited module, `packages/github-provider-adapter/src/github-http-boundary.ts`.
- M15b allowed metadata requests: fixed `GET /repos/{owner}/{repo}`, `GET /repos/{owner}/{repo}/branches/{branch}`, and `GET /repos/{owner}/{repo}/pulls?...` against `api.github.com`.
- M15b control plane: Supervisor stores dry-runs, approval records, runs, evidence, and audit records. Mutating routes require the local-control gate and reject request-body approval artifacts or authority objects.
- M15c read-only UX: Dashboard route `#/github` and CLI commands `codexhub github status`, `codexhub github metadata dry-runs list`, `codexhub github metadata runs list`, and `codexhub github metadata runs show <runId>` expose only hashes, counts, statuses, evidence ids, audit ids, and boundary booleans.
- M15c UI/CLI cannot create approvals, run the adapter, send Supervisor POST requests, persist control-plane credentials, or send GitHub network requests.
- M15.5 hardening: `audit:no-live-automation` enforces the single GitHub HTTP boundary and blocks production-source GitHub ref, merge, label, comment, reviewer, and non-draft PR mutation surfaces.
- M15.5 documents operator handling in `docs/runbooks/m15-github-provider-operator-runbook.md`, release evidence in `docs/releases/m15-github-provider-results.md`, and hardening review in `docs/reviews/m15-github-provider-hardening-review.md`.
- M16a planning: `createGithubDraftPrPlan` produces a metadata-only readiness plan for existing-branch draft PR creation. It accepts source ids from local RC readiness or review package summaries, hashes the generated title/body template summaries, requires an existing remote head branch, blocks when an existing PR is found, and never sends GitHub network requests.
- M16a authority: the plan uses action `github.draft_pr.create` with action mode `write`, requires approval, and never grants execution authority.
- M16b runtime enablement: `CODEXHUB_GITHUB_PROVIDER_ENABLED=true`, `CODEXHUB_GITHUB_DRAFT_PR_ENABLED=true`, and `CODEXHUB_GITHUB_TOKEN` configured.
- M16b control plane: Supervisor adds `/api/github/draft-prs/*` dry-run, approval, and run routes. All POST routes require the local-control gate, resolve approvals from the store, reject request-body approval artifacts or authority objects, and accept only transient hash-bound remote refs and generated title/body summaries.
- M16b HTTP boundary: the same audited `packages/github-provider-adapter/src/github-http-boundary.ts` module performs fixed preflight GETs for repo/base/head/existing-PR metadata and one fixed draft PR creation POST. It never pushes, creates refs, merges, labels, requests reviewers, comments, or creates non-draft PRs.
- M16b public output: completed runs expose run id, remote ref hashes, PR number hash, PR URL hash, response body hashes, evidence refs, audit ids, and boundary booleans only. Raw token, owner, repo, branch, URL, request body, response body, title, and PR markdown body are not persisted or returned.
- M16b approval consumption: any attempt that reaches the GitHub network boundary marks the persisted approval as used. Pre-boundary blocked attempts do not consume approval.
- M16c read-only UX: Dashboard route `#/github` adds Draft PR run metadata, and CLI adds `codexhub github draft-prs dry-runs list`, `codexhub github draft-prs approvals list`, `codexhub github draft-prs runs list`, and `codexhub github draft-prs runs show <runId>`.
- M16c generic run projection includes `github_draft_pr_run`; these views use GET only, do not read local-control keys, do not call adapter execution helpers, and do not send GitHub network requests.
- M16d fixture rehearsal: `runGithubDraftPrAcceptanceRehearsal` covers all-pass, token-missing, provider-disabled, approval-blocked, head-branch-missing, existing-pr-found, github-post-failed, and network-timeout scenarios.
- M16d CLI: `codexhub github draft-prs rehearse --fixture --scenario <name>` returns only scenario, status, readiness status, creation status, counts, and boundary booleans. It does not read local-control keys, send Supervisor POST requests, call the HTTP boundary, or create a remote PR.
- M16d Dashboard: `#/github` shows a read-only acceptance rehearsal panel. The panel does not accept tokens, does not expose approve/execute controls, and does not invoke the adapter.
- M16.5 hardening: release evidence is recorded in `docs/releases/m16-github-draft-pr-results.md`, hardening review in `docs/reviews/m16-github-draft-pr-hardening-review.md`, and the operator runbook in `docs/runbooks/m16-github-draft-pr-operator-runbook.md`.
- M17a planning: `createGithubBranchPublishPlan` produces a metadata-only readiness plan for creating a new remote branch from an approved local RC, review package, or verified patch lifecycle summary. Branches must use the `codexhub/` prefix and an existing branch blocks readiness.
- M17a authority: the plan uses action `github.branch_publish.create` with action mode `write`, requires approval, and never grants execution authority.
- M17b runtime enablement: `CODEXHUB_GITHUB_PROVIDER_ENABLED=true`, `CODEXHUB_GITHUB_BRANCH_PUBLISH_ENABLED=true`, and `CODEXHUB_GITHUB_TOKEN` configured.
- M17b control plane: Supervisor adds `/api/github/branch-publishes/*` dry-run, approval, and run routes. All POST routes require the local-control gate, resolve approvals from the store, reject request-body approval artifacts or authority objects, and accept only transient hash-bound owner/repo/base/branch/source/content inputs.
- M17b HTTP boundary: the same audited `packages/github-provider-adapter/src/github-http-boundary.ts` module performs fixed Git Data API calls for repo metadata, base ref, new branch absence, base commit tree metadata, blob creation, tree creation, commit creation, and one `codexhub/*` ref creation. It never uses local `git push`, update-ref, force, overwrite, merge, labels, reviewers, comments, or arbitrary URLs.
- M17b content rules: only repo-relative text files from the approved isolated source are accepted; v1 blocks deletions, renames, binary files, symlinks, repo-root target mutation, generated arbitrary command output, more than 100 files, files over 512 KB, or total transient upload content over 5 MB. Raw file content may be sent transiently inside the approved boundary but is never persisted or returned.
- M17b public output: completed runs expose run id, remote ref hashes, content manifest hash, file/byte counts, branch hash, commit sha hash, tree sha hash, response body hashes, evidence refs, audit ids, and boundary booleans only.
- M17b approval consumption: any attempt that reaches a GitHub network write boundary marks the persisted approval as used. Pre-boundary blocked attempts do not consume approval.
- M17c read-only UX: Dashboard route `#/github` adds Branch Publish run metadata, and CLI adds `codexhub github branch-publishes dry-runs list`, `approvals list`, `runs list`, and `runs show <runId>`.
- M17c generic run projection includes `github_branch_publish_run`; these views use GET only, do not read local-control keys, do not call adapter execution helpers, and do not send GitHub network requests.
- M17d fixture rehearsal: `runGithubBranchPublishAcceptanceRehearsal` covers all-pass, token-missing, provider-disabled, approval-blocked, branch-exists, content-manifest-blocked, blob-create-failed, tree-create-failed, commit-create-failed, ref-create-failed, and network-timeout scenarios.
- M17d CLI/Dashboard: the branch publish rehearsal returns only scenario, status, readiness status, publish status, counts, and boundary booleans; it does not read local-control keys, send Supervisor POST requests, call the HTTP boundary, or create a remote branch.
- M17.5 hardening: release evidence is recorded in `docs/releases/m17-github-branch-publish-results.md`, hardening review in `docs/reviews/m17-github-branch-publish-hardening-review.md`, and the operator runbook in `docs/runbooks/m17-github-branch-publish-operator-runbook.md`.
- M18a planning: `createGithubPublishDraftPrChainPlan` creates a metadata-only chain plan from existing branch-publish and draft-PR metadata. It requires separate branch-publish and draft-PR approvals, records only source ids/hashes/statuses, and grants no execution authority.
- M18b chain control plane: Supervisor adds `/api/github/publish-draft-pr-chains/*` dry-run and run summary routes. POST routes still use the local-control gate and reject request-body approval artifacts or authority objects. The chain route does not call GitHub directly; it projects already governed child run records.
- M18b sequencing: branch publish failure prevents draft PR progression. Draft PR failure after branch creation records recovery metadata only; it does not delete the remote branch automatically.
- M18c PR lifecycle observation is conservative in this slice: `createGithubRemotePrLifecycleSummary` projects lifecycle/check status from existing metadata and fixture summaries only. No additional live GitHub GET boundary is added in M18.
- M18d read-only UX: Dashboard route `#/github` adds publish-to-draft-PR chain records and acceptance rehearsal summaries. CLI adds `codexhub github publish-draft-pr-chains dry-runs list`, `runs list`, `runs show <runId>`, and `rehearse --fixture --scenario <name>`.
- M18e fixture rehearsal: `runGithubPublishDraftPrAcceptanceRehearsal` covers all-pass, publish-blocked, branch-published-pr-blocked, draft-pr-created-checks-pending, checks-failed, checks-passed, stale-branch, and network-timeout scenarios.
- M18.5 hardening: release evidence is recorded in `docs/releases/m18-remote-publish-draft-pr-results.md`, hardening review in `docs/reviews/m18-remote-publish-hardening-review.md`, and the operator runbook in `docs/runbooks/m18-remote-publish-operator-runbook.md`.
- M19 runtime enablement: `CODEXHUB_GITHUB_PROVIDER_ENABLED=true`, `CODEXHUB_GITHUB_PR_LIFECYCLE_OBSERVER_ENABLED=true`, and `CODEXHUB_GITHUB_TOKEN` configured.
- M19 control plane: Supervisor adds `/api/github/pr-lifecycle/*` dry-run, approval, and run routes. All POST routes require the local-control gate, resolve approvals from the store, reject request-body approval artifacts or authority objects, and accept only transient hash-bound owner/repo/base/head/PR/commit inputs.
- M19 HTTP boundary: the same audited `packages/github-provider-adapter/src/github-http-boundary.ts` module performs fixed read-only GET requests for repo metadata, PR metadata or existing-PR lookup, branch ref metadata, combined commit status, and check-run summary. It never reads raw check logs, comments, reviews, labels, reviewers, merge state changes, or arbitrary URLs.
- M19 public output: completed observations expose run id, remote ref hashes, PR number hash, PR URL hash, commit sha hash, PR state summary, status/check counts, response body hashes, evidence refs, audit ids, and boundary booleans only. Raw token, owner, repo, branch, URL, PR body, response body, check logs, comments, and review bodies are not persisted or returned.
- M19 approval consumption: any attempt that reaches the GitHub PR lifecycle network boundary marks the persisted approval as used. Pre-boundary blocked attempts do not consume approval.
- M19 read-only UX: Dashboard route `#/github` adds PR Lifecycle run metadata and a fixture-only PR lifecycle rehearsal panel. CLI adds `codexhub github pr-lifecycle dry-runs list`, `approvals list`, `runs list`, `runs show <runId>`, and `rehearse --fixture --scenario <name>`.
- M19 rehearsal: `runGithubPrLifecycleAcceptanceRehearsal` covers all-pass, token-missing, provider-disabled, approval-blocked, pr-not-found, checks-pending, checks-failed, checks-passed, stale-branch, and network-timeout scenarios without invoking the network boundary.
- M19 hardening: release evidence is recorded in `docs/releases/m19-github-pr-lifecycle-results.md`, hardening review in `docs/reviews/m19-github-pr-lifecycle-hardening-review.md`, and the operator runbook in `docs/runbooks/m19-github-pr-lifecycle-operator-runbook.md`.
- Runtime owner/repo/base/head values are transient and must hash-match the persisted dry-run before a request is sent. Public responses expose only ids, hashes, counts, statuses, evidence refs, audit ids, and boundary booleans.
- Forbidden operations: local git push, update-ref, force, overwriting an existing branch, merge, delete, labels, reviewers, comments, milestones, deployments, releases, non-draft PR creation, and arbitrary endpoint passthrough. The only allowed ref creation is the M17 approved `codexhub/*` new-branch publish path.
- Provider cannot grant authority. CodexHub policy, approval, evidence, and audit remain authoritative.
