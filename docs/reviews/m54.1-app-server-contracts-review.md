# M54.1 Codex App Server Contracts Review

Status: completed.

## Findings

No blocking findings were found in this contracts-only round.

## Review Scope

Reviewed:

- App Server wire summary schema.
- Thread, turn, and event mirror schemas.
- Approval bridge metadata and decision count validation.
- Protocol drift status and live-dispatch blocking rule.
- Forbidden-field negative tests.

Not reviewed:

- App Server transport implementation.
- JSONL codec behavior.
- Real account/rate-limit reads.
- Thread/turn creation or event stream ingestion.
- Supervisor route wiring.
- Store table persistence.

## Boundary Review

The M54.1 implementation preserves these invariants:

- App Server records store hashes, summaries, counts, status, evidence refs,
  audit ids, timestamps, and explicit boundary booleans only.
- Thread mirrors may store `pathHash`, never raw paths.
- Turn mirrors store input/output summary hashes, never user input or model
  output bodies.
- Approval bridge records require explicit status and do not allow silent
  approval.
- Unknown or incompatible protocol drift must block live dispatch.
- Supervisor and adapters still have no direct connection in this round.

## Residual Risks

- Store persistence is not available until M54.2, so these records are not yet
  round-tripped through SQLite.
- Adapter code is not available until M54.3, so protocol drift detection is
  still a contract shape, not a runtime check.
- M57 will need a later contract review if real dispatch requires additional
  execution status fields.

## Recommended Next Round

M54.2 store:

- Add metadata-only repositories and SQLite tables for the six M54 record
  types.
- Add round-trip tests and forbidden-field persistence tests.
- Keep SQLite runtime bindings isolated to `packages/store-sqlite`.
