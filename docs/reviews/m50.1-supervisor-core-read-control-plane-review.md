# M50.1 Supervisor Core Read Control Plane Review

Status: completed.

## Findings

No blocking findings were found in this round.

## Review Scope

Reviewed:

- Root-level Supervisor read routes for capabilities, accounts, clients, tasks,
  workflows, approvals, evidence, and audit.
- Metadata-only projections for evidence refs and audit events.
- Degraded states for account, client, and task surfaces that depend on future
  M51 contracts and store models.
- Test coverage for raw prompt, raw body, raw path, and raw audit action
  suppression.
- Governance registration and M50.1 closeout docs.

Not reviewed:

- POST mutation shell implementation.
- New contracts or store migrations.
- Real account, profile, Codex App Server, Browser, Electron/CDP, GitHub, or
  external process operation.
- Dashboard, CLI, or MCP UX changes.

## Boundary Review

The M50.1 implementation preserves these invariants:

- New routes are `GET` read routes only.
- Route handlers use static projections or store read repositories; they do not
  call capability adapters.
- Evidence and audit detail routes return ids, hashes, summaries, statuses,
  evidence refs, audit ids, and boundary booleans only.
- Account, client, and task routes explicitly report `missing-contracts-store`
  instead of inventing incomplete models.
- Request-body approval artifacts and execution authorities remain untrusted in
  the existing global POST guard model.

## Residual Risks

- M50.2 must test mutation-shell routes before adding new POST behavior.
- M51 still needs explicit shared schemas and SQLite round trips for accounts,
  clients, tasks, quota, diagnosis, recovery, evidence, and audit projections.
- Public response discipline must remain strict as soon as task prompts, raw
  diffs, App Server events, or account/client records exist.

## Recommended Next Round

Start M50.2:

- Add explicit tests for root-level POST mutation shell gates.
- Keep local-control token, trusted loopback Origin, Host validation, and
  request-body authority rejection centralized.
- Add only dry-run or decision shells that create metadata-only evidence/audit
  records.
- Continue to block direct route-to-adapter execution.
