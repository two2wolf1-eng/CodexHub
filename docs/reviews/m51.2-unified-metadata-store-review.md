# M51.2 Unified Metadata Store Review

Status: completed.

## Findings

No blocking findings were found in this round.

## Review Scope

Reviewed:

- `store-core` async repository interface additions.
- `store-sqlite` table creation and generic metadata repository.
- M51 metadata round-trip test coverage.
- Forbidden-field negative coverage before persistence.
- SQLite isolation and import-boundary behavior.

Not reviewed:

- Supervisor read or POST route changes.
- ChatGPT Business adapter implementation.
- Chrome profile registry runtime behavior.
- Browser, Electron/CDP, Codex App Server, GitHub, account, or admin operation.

## Boundary Review

The M51.2 implementation preserves these invariants:

- `store-core` contains no SQLite runtime dependency.
- SQLite bindings remain isolated to `packages/store-sqlite`.
- Tables use the existing metadata payload pattern rather than storing raw
  private columns.
- Store tests parse records through M51 contracts before persistence.
- Query filtering is metadata-only and does not inspect raw payload bodies.

## Residual Risks

- The generic repository does not validate arbitrary runtime objects by itself;
  producers must keep parsing through contracts before save.
- Supervisor projections still need M51.3 to avoid direct adapter calls and
  sanitize public response bodies.
- Existing databases receive `CREATE TABLE IF NOT EXISTS` initialization but no
  data backfill; this is expected for new M51 record families.

## Recommended Next Round

Start M51.3:

- Replace Supervisor `/accounts`, `/clients`, and `/tasks` placeholders with
  store-backed metadata projections.
- Make task create/recover POST shells persist `CodexTaskIntent`,
  `CodexTaskRun`, and `CodexRecoveryRun` records without live execution.
- Preserve local-control token, trusted Origin/Host, evidence, and audit guards.
