# M50.3 Supervisor Mutation Shells Review

Status: completed.

## Findings

No blocking findings were found in this round.

## Review Scope

Reviewed:

- Root-level Supervisor POST shells for workflow dry-run, approval decision,
  task creation, and task recovery.
- Shared POST guard behavior inherited from M50.2.
- Request-body authority rejection.
- Metadata-only response shape.
- Store-backed evidence and audit trace metadata.
- Focused Supervisor test coverage.
- M50.3 governance registration and closeout docs.

Not reviewed:

- M51 account, client, task, diagnosis, recovery, or quota contracts.
- New SQLite repositories or migrations.
- Real workflow execution, scheduler behavior, Browser, Electron/CDP, Codex App
  Server, ChatGPT Business, GitHub, or external process operation.
- Dashboard, CLI, or MCP UX changes.

## Boundary Review

The M50.3 implementation preserves these invariants:

- POST shells are protected by the M50.2 local-control, trusted Origin, and
  trusted Host guard.
- Request-body approval artifacts and execution authority are rejected, not
  converted into authority.
- Accepted shell traces store only hashes, booleans, status, summaries, evidence
  ids, and audit ids.
- Public responses do not return raw prompt, body, path, reason, authority,
  adapter output, token, credential, session, or account secret material.
- Task create and task recovery do not become real mutations before M51
  contracts and store models.
- Route handlers still do not call adapters directly.

## Residual Risks

- The shell response shapes are still local server objects, not shared contracts;
  M51 should move task/account/client/workflow DTOs into `packages/contracts`.
- Task create and recovery are intentionally blocked; operator UX should present
  these states as setup blockers rather than failures.
- Future approval decision work must resolve authority from store-backed
  approval artifacts, not from request bodies.

## Recommended Next Round

Start M51.1 contracts:

- Add shared schemas for accounts, clients, tasks, quota, diagnosis, recovery,
  approval decision traces, and Supervisor shell responses.
- Include redaction/hash-only tests for forbidden fields.
- Keep store migrations and runtime adapters out until the contract tests pass.
