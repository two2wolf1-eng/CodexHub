## Boundary Review

The M50.4 implementation preserves these invariants:

- Store-disabled shell requests return `store-unavailable` rather than success.
- Store-disabled shell responses do not invent evidence or audit ids.
- Missing local-control tokens are rejected before route logic.
- Malicious Origin and Host headers are rejected before route logic.
- Public responses do not leak raw prompt, body, path, reason, token, credential,
  session, or account secret material.
- No adapter path or product route behavior changed.

## Residual Risks

- Shell response shapes remain local server objects until M51 contracts define
  shared DTOs.
- The guard regression is server-test based; Dashboard, CLI, and MCP UX should
  stay read-only until explicit guided UX rounds exist.
- Store availability is tested with `disableStore`; later real persistence
  failures should keep returning metadata-only degraded states.
