# M54.3 Codex App Server Adapter Review

Status: completed.

## Findings

No blocking findings were found in this adapter shell round.

## Review Scope

Reviewed:

- Adapter manifest and dry-run plan.
- JSONL request, notification, and response codec.
- In-memory transport public summaries.
- Initialize lifecycle controller.
- Focused tests for not initialized, duplicate initialize, and missing response.

Not reviewed:

- Real App Server process launch.
- Real account, rate-limit, thread, turn, or event methods.
- Approval bridge runtime.
- Protocol drift runtime.
- Supervisor route wiring.

## Boundary Review

The M54.3 implementation preserves these invariants:

- The adapter does not start an external process.
- The fixture transport exposes hash/count/method summaries, not raw sent lines.
- Initialize returns M54 wire summaries and an M51 App Server session record.
- Duplicate initialize is blocked.
- Operations before initialize can be classified as blocked.
- Public outputs do not contain private client/session/request ids.

## Residual Risks

- The codec accepts JSON-compatible params because a future real transport must
  send protocol payloads; M54.3 tests only assert that public summaries do not
  persist raw payloads.
- In-memory transport is not a substitute for real process management; M54.4+
  must add authority, audit, and drift checks before real process boundaries.
- Response method classification is inferred for initialize in this round; later
  request correlation should keep method hashes without raw transcript storage.

## Recommended Next Round

M54.4 account/rate limits:

- Add account/read and account/rateLimits/read helpers over the fixture JSONL
  transport.
- Map account identity into `CodexAccountBinding` and rate limits into
  `QuotaSnapshot`.
- Keep raw account payloads out of public results and persistence.
