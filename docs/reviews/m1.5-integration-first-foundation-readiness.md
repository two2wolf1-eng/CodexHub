# M1.5 Integration-First Foundation Readiness Review

## Decision

M0/M1 remains a valid foundation, but M2a should start only after this M1.5 hardening gate passes.

## Current Evidence

- `pnpm verify:foundation` passed before this round.
- The repository contained 16 Nx projects and the expected M0/M1 governance files.
- Existing Supervisor local control, approval artifact authority, recursive evidence redaction, write approval policy, and read-only Codex boundary tests were already present.

## Readiness Gap Closed By This Round

- Integration-first capability contracts are now part of the shared contract language.
- `dry-run` and `admin` are explicit action modes instead of policy comments.
- Governance files now distinguish authority providers from capability providers.
- Integration decisions and scaffold health now cover M2a readiness artifacts.
- No new external process boundary is enabled by this review.

## M2a Entry Gate

Before implementing `codex-exec-adapter`, the following must be true:

- `pnpm verify:foundation` passes.
- `.codexhub/integrations.yaml` keeps Codex CLI disabled until the adapter is implemented behind policy gates.
- Any new process boundary is added to `audit:no-live-automation` only in the same round that adds focused process-boundary tests.
- New adapter execution requires `ExecutionAuthority` and produces evidence plus audit.
