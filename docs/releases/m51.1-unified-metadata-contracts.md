# M51.1 Unified Metadata Contracts

Status: completed.

## GSD Spec

- Goal: define the M51 shared language for Business workspace mirrors, Codex
  account/client/task records, quota, leases, evidence bundles, and human
  checkpoints so M50 Supervisor placeholders can be replaced safely.
- Scope: `packages/contracts`, contract tests, scaffold health registration,
  release/review/runbook docs.
- Non-scope: no SQLite tables, Supervisor route behavior, ChatGPT Business
  adapter, Chrome profile registry, browser automation, Codex App Server
  dispatch, live admin operation, or account mutation.
- Acceptance criteria: new schemas parse metadata-only records; negative tests
  reject raw prompt, diff, path, body, token, cookie, session, MFA, credential,
  and browser storage fields; contracts build and export registration passes.
- Hard boundaries: records store only ids, hashes, summaries, statuses, counts,
  timestamps, evidence refs, audit ids, and boundary booleans.
- Affected apps/packages: `packages/contracts`, docs, and
  `tools/scaffold-health.ts`.
- Risk level: critical, because these contracts become the shared DTO boundary
  for M51-M53 control-plane and store work.

## GStack Plan

- Plan: add the shared schemas before touching store or apps.
- Build: keep all models strict, metadata-only, and hash/ref based.
- Review: inspect forbidden-field coverage and scaffold export registration.
- QA: run focused contracts tests/build and foundation boundary audits.
- Ship: commit independently before store-core/store-sqlite work begins.
- Retro: M51.2 can add persistence against stable schemas.
