# M54.4 App Server Account And Rate Limits

Status: completed.

## GSD Spec

- Goal: add App Server `account/read` and `account/rateLimits/read` helpers that
  project raw fixture responses into metadata-only account and quota records.
- Scope: `packages/codex-app-server-adapter`, focused adapter tests,
  release/review/runbook docs.
- Non-scope: no real App Server process launch, real account connection,
  Supervisor route wiring, task dispatch, thread/turn runtime, event stream
  ingestion, approval bridge runtime, protocol drift runtime, Electron/CDP
  observation, or browser observation.
- Acceptance criteria: account reads produce `CodexAccountBinding`; rate-limit
  reads produce `QuotaSnapshot`; both require initialize first, use JSONL wire
  summaries, and do not return raw account ids, email, workspace id, reset time,
  request id, or response body.
- Hard boundaries: no raw prompt, diff, path, body, token, cookie, session, MFA,
  browser storage, account credential, command payload, file payload, approval
  secret, raw schema, or raw JSONL transcript is persisted.
- Affected apps/packages: `packages/codex-app-server-adapter`, docs.
- Risk level: high, because this reads account/quota-shaped data while keeping
  it fixture-only and hash-only.

## GStack Plan

- Plan: add account/quota helpers on top of the initialized fixture transport.
- Build: consume response payloads in memory, hash sensitive identifiers, and
  return contract-backed projections.
- Review: verify no raw account, workspace, email, reset, or request ids leave
  public results.
- QA: run focused adapter test/build/lint and foundation static audits.
- Ship: commit independently before thread/turn/event helpers.
- Retro: App Server account/quota metadata can now be rehearsed safely.
