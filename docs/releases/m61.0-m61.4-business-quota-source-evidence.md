# M61.0-M61.4 Business Quota Source Evidence

## GSD

- Goal: establish the first M61 checkpoint for Business quota readiness debug.
- Scope: entry gate, source map, official documentation probe, contract gap review, and evidence matrix v1.
- Non-scope: no live account operation, no login flow, no UI scraping, no adapter activation.
- Acceptance: clean entry verification, M61 contracts, metadata-only tests, and source ranking draft.
- Hard boundaries: only ids, hashes, summaries, statuses, counts, refs, and audit ids may be persisted.
- Affected packages: `contracts`, `business-quota-debug-kernel`, `store-core`, `store-sqlite`, `supervisor`.
- Risk: high, because quota readiness touches account and workspace governance.

## Rounds Covered

1. M61.0 Entry Gate: `pnpm verify:foundation` passed before M61 edits.
2. M61.1 Source Map: candidate sources are App Server rate limits, official APIs or analytics, Business credits, manual export, and UI reference.
3. M61.2 Official Docs Probe: Business credits, spend controls, roles, seats, and App Server account/rate limits were confirmed as source categories.
4. M61.3 Contract Gap Review: `QuotaSnapshot` remains the normalized quota record; M61 adds debug probes around source and permission readiness.
5. M61.4 Evidence Matrix v1: field sensitivity is expressed as status-only, count-only, hash-only, summary-only, or forbidden.
