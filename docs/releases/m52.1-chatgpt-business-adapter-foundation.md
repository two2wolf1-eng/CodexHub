# M52.1 ChatGPT Business Adapter Foundation

Status: completed.

## GSD Spec

- Goal: add `@codexhub/chatgpt-business-adapter` as a fixture-first,
  read-only adapter foundation for Business workspace identity, membership
  mirror, and quota metadata.
- Scope: new package, public exports, focused adapter tests, workspace package
  registration, scaffold health registration, release/review/runbook docs.
- Non-scope: no real ChatGPT Business network calls, browser profile access,
  invite/remove/replace live admin, Supervisor route wiring, Codex App Server
  dispatch, or account mutation.
- Acceptance criteria: manifest validates; read plan is metadata-only; fixture
  member sync isolates one failed member but blocks all-member failure; workspace
  identity and quota outputs are hash/count only; admin helpers stay dry-run
  blocked with approval planning metadata.
- Hard boundaries: no raw member, workspace, email, display name, reset time,
  prompt, diff, path, body, token, cookie, session, MFA, credential, or browser
  storage is returned or persisted.
- Affected apps/packages: `packages/chatgpt-business-adapter`,
  `tsconfig.base.json`, `pnpm-lock.yaml`, docs, and
  `tools/scaffold-health.ts`.
- Risk level: high, because this introduces a future external-network adapter
  boundary, although M52.1 itself stays fixture-only.

## GStack Plan

- Plan: create package shell, then manifest/plan, read-only fixture sync,
  identity/quota helpers, and admin dry-run blockers.
- Build: export only public package entrypoints and reuse M51 contracts.
- Review: check no external process, network runner, browser state read, or live
  admin path exists.
- QA: run adapter focused test/build and foundation audits.
- Ship: commit independently before M53 browser profile registry work.
- Retro: M52 has a governed read-only adapter skeleton that can produce M51
  metadata for later store/Supervisor wiring.
