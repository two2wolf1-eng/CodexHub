# M50.3 Supervisor Mutation Shells

Status: completed.

## GSD Spec

- Goal: add guarded Supervisor POST shells for workflow dry-run, approval
  decision, task creation, and task recovery without enabling live execution.
- Scope: `apps/supervisor/src/server.ts`, `apps/supervisor/src/server.test.ts`,
  release/review/runbook docs, `.codexhub` registration, scaffold health
  registration, and the M49-M60 backlog.
- Non-scope: no workflow adapter execution, task contract model, task store
  repository, account pool, Browser/Electron/Codex App Server/ChatGPT Business
  operation, GitHub remote write, push, or pull request.
- Acceptance criteria: the four POST shells are protected by the M50.2 guard,
  reject request-body authority, write metadata-only evidence and audit refs
  when the store is available, and return only hashes, summaries, statuses,
  evidence refs, audit ids, and boundary booleans.
- Hard boundaries: request-body approval artifacts and execution authority are
  never trusted; task create and recovery remain blocked until M51 contracts and
  store models exist; route handlers do not call adapters directly.
- Affected apps/packages: `apps/supervisor`, docs, `.codexhub`, and
  `tools/scaffold-health.ts`.
- Risk level: critical, because these are the first root-level mutating control
  plane surfaces for later real-capability work.

## GStack Plan

- Plan: add only metadata shell behavior on top of the hardened M50.2 guard.
- Build: implement POST shells for workflow dry-run, approval decision, task
  create, and task recovery.
- Review: confirm responses and persisted records exclude raw prompt, body,
  path, reason, authority, adapter output, and live execution data.
- QA: run focused Supervisor tests/build, scaffold health, audits, foundation
  verification, diff check, and git status.
- Ship: commit independently after verification passes.
- Retro: M51 can add contracts and store records before any real task mutation
  path is allowed to move past the shell.
