# M51.3 Supervisor Metadata Projections

Status: completed.

## GSD Spec

- Goal: replace M50 placeholder account, client, and task read surfaces with
  M51 store-backed metadata projections, and record task create/recover POST
  shells as governed metadata without live dispatch.
- Scope: `apps/supervisor`, focused Supervisor tests, scaffold health
  registration, release/review/runbook docs.
- Non-scope: no ChatGPT Business adapter, Chrome profile runtime, browser
  automation, Codex App Server dispatch, account mutation, or live admin
  operation.
- Acceptance criteria: `/accounts`, `/clients`, and `/tasks` return store
  projections; task create records `CodexTaskIntent` and `CodexTaskRun`; task
  recover records `CodexRecoveryRun`; public responses expose only hashes,
  summaries, statuses, counts, evidence refs, and audit ids.
- Hard boundaries: Supervisor routes do not call adapters directly; all POST
  routes keep local-control token, trusted Origin/Host, body-authority
  rejection, evidence, and audit guards; no raw prompt, diff, path, body, token,
  cookie, session, MFA, credential, or browser storage is returned or stored.
- Affected apps/packages: `apps/supervisor`, docs, and
  `tools/scaffold-health.ts`.
- Risk level: critical, because Supervisor becomes the public read/control
  projection for M51 metadata.

## GStack Plan

- Plan: wire read projections first, then task create/recover metadata shells.
- Build: read only from M51 store repositories and project safe fields.
- Review: inspect routes for direct adapter calls, response leakage, and POST
  gate regressions.
- QA: run Supervisor focused test/build and foundation boundary audits.
- Ship: commit independently before M52 adapter work.
- Retro: M50 `missing-contracts-store` blockers are removed for accounts,
  clients, and tasks while execution remains disabled.

## Changes

- Replaced `/accounts`, `/clients`, and `/tasks` placeholder responses with
  M51 metadata projections from `CodexHubStore`.
- Added safe projection items with `kind`, `recordHash`, `status`, `summary`,
  metadata counts, evidence refs, and audit ids only.
- Updated task create POST shell to persist a `CodexTaskIntent` and
  `CodexTaskRun` with live execution disabled.
- Updated task recovery POST shell to persist a `CodexRecoveryRun` requiring
  human review.

  forged authority rejection behavior.
