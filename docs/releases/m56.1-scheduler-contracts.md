# M56.1 Scheduler Contracts

Status: completed.

## GSD Spec

- Goal: add shared scheduler vocabulary for account/client readiness and
  dispatch preflight summaries.
- Scope: `packages/contracts`, `tools/scaffold-health.ts`, focused contracts
  tests, release/review/runbook docs.
- Non-scope: no scheduler runtime, lease acquisition, Supervisor projection,
  App Server dispatch, worktree mutation, or browser/Electron automation.
- Acceptance criteria: contracts parse account/client scheduling projections and
  scheduler selection summaries using hashes, statuses, scores, counts, evidence
  refs, and audit ids only.
- Hard boundaries: no raw prompt, diff, path, body, token, cookie, session, MFA,
  storage, profile path, command line, network body, or live automation.
- Affected apps/packages: `packages/contracts`, `tools`, docs.
- Risk level: medium, because this creates shared dispatch vocabulary without
  enabling execution.

## GStack Plan

- Plan: extend shared language before adding scheduler kernel behavior.
- Build: add account/client scheduling statuses and metadata-only projections.
- Review: verify dispatcher readiness remains declarative and governance-owned.
- QA: run focused contracts test/build/lint and foundation static audits.
- Ship: commit M56.1 independently before the scheduler package.
- Retro: downstream M56 rounds can now score accounts and clients consistently.
