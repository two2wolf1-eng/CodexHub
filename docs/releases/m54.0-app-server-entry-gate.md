# M54.0 Codex App Server Entry Gate

Status: completed.

## GSD Spec

- Goal: close the M53.5 foundation gate and prepare M54 App Server work with
  explicit evidence, safety boundaries, and operator instructions.
- Scope: release, review, and runbook docs for the M54 entry gate.
- Non-scope: no App Server transport, adapter package, Supervisor route change,
  Codex task dispatch, Electron/CDP automation, browser automation, or store
  schema change.
- Acceptance criteria: clean git entry state, `pnpm verify:foundation` passes,
  upstream App Server protocol source is reviewed, and M54.1 can begin from
  documented constraints.
- Hard boundaries: no raw prompt, diff, path, body, token, cookie, session, MFA,
  browser storage, account credential, command body, file body, or approval
  secret is read, returned, or persisted.
- Affected apps/packages: docs only.
- Risk level: medium, because this opens the planning gate for real App Server
  dispatch while keeping M54.0 documentation-only.

## Upstream Protocol Reference

Reviewed on 2026-05-07:

- <https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md>

M54 uses that upstream README as the current protocol source. The entry
assumption is that App Server clients speak JSON-RPC-style messages over JSONL
stdio, must send `initialize`, then send an `initialized` notification, and
should treat generated TypeScript or JSON Schema output as version-specific
drift evidence.

## M54 Boundaries

- Supervisor routes must not call App Server adapters directly.
- POST routes remain protected by local-control token, trusted Origin/Host,
  request-body authority rejection, evidence, and audit traces.
- Adapter records may store only id, hash, summary, status, counts, timestamps,
  evidence refs, audit ids, and explicit boundary booleans.
- Command and file approval bridge records must not silently approve anything.
- Protocol drift detection blocks incompatible or unknown live dispatch.
