# M57.6-M57.7 Dispatch Lifecycle

Status: completed.

## GSD Spec

- Goal: connect ready M57 task preflight results to an App Server
  initialize/thread/turn/event lifecycle and write diagnosis records whenever the
  lifecycle cannot prove completion.
- Scope: `packages/orchestrator-kernel`, its public dependency on
  `@codexhub/codex-app-server-adapter`, focused orchestrator tests, and this
  release/review/runbook documentation.
- Non-scope: no Supervisor POST `/tasks` route wiring, no real GitHub closure,
  no command/file approval auto-grant, no Electron or browser automation.
- Acceptance criteria: blocked preflight never calls App Server, successful fake
  lifecycle requires a terminal event before marking completed, initialization
  failure writes `CodexTaskDiagnosis`, and focused test/build/lint plus static
  audits pass.
- Hard boundaries: only ids, hashes, summaries, statuses, counts, timestamps,
  evidence refs, and audit ids may be returned; raw prompt, diff, path, body,
  token, cookie, session, MFA, storage, and private JSON-RPC ids must not be
  serialized.
- Affected apps/packages: `packages/orchestrator-kernel`, `pnpm-lock.yaml`, and
  M57.6/M57.7 docs.
- Risk level: high, because this composes the live-capable App Server boundary
  with task run state.

## GStack Plan

- Plan: keep lifecycle orchestration in `orchestrator-kernel` and leave process
  start inside the governed adapter boundary from M57.5.
- Build: add `runCodexTaskDispatchLifecycle` and lifecycle failure mapping.
- Review: confirm lifecycle success requires terminal event evidence and failures
  create diagnosis instead of pretending success.
- QA: run focused orchestrator tests/build/lint and static audits.
- Ship: commit M57.6/M57.7 independently.
- Retro: M57.8 can now wire Supervisor `POST /tasks` to this orchestrator shell
  without directly calling adapters from routes.
