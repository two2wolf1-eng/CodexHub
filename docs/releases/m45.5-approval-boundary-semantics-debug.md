# M45.5 Approval Boundary Semantics Debug

Status: completed

## Goal

Make late-stage approval consumption and boundary truth harder to regress across deployment, policy telemetry, controlled Browser/Electron/MCP writes, GitHub, and workflow recovery surfaces.

## Scope

- Supervisor approval consumption regression tests.
- Store-resolved dry-run lookup for M44/M45 run paths.
- Documentation, orchestration, and scaffold health registration.

## Findings

- M44/M45 run routes accepted public `dryRunId` in request bodies, but their store lookups resolved only internal record ids. This caused approved run attempts to return `404` before exercising approval consumption and boundary-state behavior.
- Existing tests did not prove that M44/M45 approvals stay unused on pre-boundary blocks and become used exactly once after a governed execution starts.

## Fixes

- Added store-resolved dry-run lookup fallback by public `dryRunId` for real policy backend, real telemetry export, and controlled Browser/Electron/MCP write run families.
- Added table-driven tests for M44/M45 pre-boundary blocks, boundary-started runs, reused approvals, and metadata-only public responses.
- Tightened deployment operation coverage so failed boundary attempts consume the matching approval exactly once while preserving boundary booleans.

## Verification

- `pnpm nx run supervisor:test --skip-nx-cache` passed.
- Full foundation gates remain required before commit.

## Rollback

Revert this round to restore the previous M44/M45 dry-run lookup behavior and remove the M45.5 tests/docs/scaffold registration.
