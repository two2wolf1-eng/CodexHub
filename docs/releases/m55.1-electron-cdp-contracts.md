# M55.1 Electron/CDP And OS Process Contracts

Status: completed.

## GSD Spec

- Goal: add shared metadata language for Codex Desktop health, diagnosis hints,
  and allowlisted OS process observation.
- Scope: `packages/contracts`, focused contracts tests,
  release/review/runbook docs.
- Non-scope: no real process enumeration, CDP HTTP fetch, WebSocket connection,
  `Runtime.evaluate`, DOM mutation, click/type, network body capture, or
  Supervisor wiring.
- Acceptance criteria: contracts parse OS process summaries and Codex Desktop
  health snapshots with hashes/counts/status only, reject raw paths, and expose
  diagnosis hints including `desktop_ui_frozen`, `app_server_unresponsive`,
  `quota_depleted`, and `codex_logged_out`.
- Hard boundaries: no raw path, command line, network body, prompt, token,
  cookie, session, MFA, storage, DOM payload, or process launch is allowed.
- Affected apps/packages: `packages/contracts`, docs.
- Risk level: medium, because this creates shared diagnosis vocabulary without
  enabling observation runtime.

## GStack Plan

- Plan: extend contracts before kernel/adapter runtime changes.
- Build: add OS process metadata and Codex Desktop health schemas.
- Review: verify only hashes, rounded metrics, booleans, counts, and hints are
  stored.
- QA: run focused contracts test/build/lint and foundation static audits.
- Ship: commit independently before M55.2 runtime discovery.
- Retro: downstream packages can now use one shared language for desktop health.
