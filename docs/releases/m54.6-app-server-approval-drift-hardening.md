# M54.6 App Server Approval And Drift Hardening

Status: completed.

## GSD Spec

- Goal: add metadata-only approval bridge and protocol drift detector for Codex
  App Server rehearsal.
- Scope: `packages/codex-app-server-adapter`, focused adapter tests,
  release/review/runbook docs.
- Non-scope: no real App Server process launch, real approval decision, silent
  command/file approval, Supervisor route wiring, Scheduler, task orchestrator,
  Electron/CDP observation, or browser observation.
- Acceptance criteria: approval request events produce bridge records with
  hashes/counts/status only; compatible protocol baselines do not block;
  unknown or incompatible drift blocks live dispatch; no raw proposal, schema,
  JSONL transcript, prompt, diff, path, body, token, cookie, session, MFA, or
  storage data is returned.
- Hard boundaries: adapter remains a capability provider only. Governance owns
  policy, approval, evidence, and audit decisions.
- Affected apps/packages: `packages/codex-app-server-adapter`, docs.
- Risk level: high, because this prepares the live dispatch boundary while
  preserving default blocking behavior.

## GStack Plan

- Plan: add bridge/drift helpers after thread/turn/event metadata mirrors.
- Build: map approval request notifications into bridge records and compare
  protocol baseline metadata by hash/counts.
- Review: verify no silent approval and no raw schema/proposal storage.
- QA: run focused adapter test/build/lint and foundation static audits, then
  full M54 `verify:foundation`.
- Ship: commit M54.6 independently as the M54 closeout.
- Retro: App Server adapter can now rehearse initialize, account/quota,
  thread/turn/event, approval waiting, and protocol drift without live process
  launch.
