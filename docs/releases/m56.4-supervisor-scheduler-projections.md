# M56.4 Supervisor Scheduler Projections

Status: completed.

## GSD Spec

- Goal: expose scheduler-ready metadata through Supervisor `/accounts`,
  `/clients`, and `/tasks` read routes.
- Scope: `apps/supervisor`, Supervisor tests, package dependency wiring, lockfile,
  release/review/runbook docs.
- Non-scope: no adapter calls, real dispatch, lease persistence mutation, worktree
  creation, browser automation, Electron action, or OS process observation.
- Acceptance criteria: GET routes include scheduler status/count/score metadata
  while preserving local-control POST guards and metadata-only responses.
- Hard boundaries: Supervisor routes must not call adapters directly and must not
  return raw prompt, diff, path, body, token, cookie, session, MFA, storage,
  command line, account identifiers, or profile paths.
- Affected apps/packages: `apps/supervisor`, lockfile, docs.
- Risk level: medium, because this exposes scheduler readiness in the control
  plane without execution authority.

## GStack Plan

- Plan: use the M56 scheduler kernel from Supervisor read projections only.
- Build: add scheduler summaries to `/accounts`, `/clients`, and `/tasks`.
- Review: confirm `dispatchAllowed` and direct adapter execution remain false.
- QA: run focused Supervisor test/build/lint and foundation static audits.
- Ship: commit independently before M56 hardening.
- Retro: Supervisor now surfaces scheduler readiness without bypassing governance.
