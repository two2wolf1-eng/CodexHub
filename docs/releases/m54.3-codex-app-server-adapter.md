# M54.3 Codex App Server Adapter

Status: completed.

## GSD Spec

- Goal: create `@codexhub/codex-app-server-adapter` with a fixture-first App
  Server manifest, dry-run plan, JSONL codec, in-memory stdio-style transport,
  and initialize lifecycle.
- Scope: new adapter package, TypeScript path registration, scaffold health
  registry, focused adapter tests, release/review/runbook docs.
- Non-scope: no real process spawn, real account read, real rate-limit read,
  real thread/turn creation, event stream ingestion runtime, approval bridge
  runtime, protocol drift runtime, Supervisor route wiring, Electron/CDP
  observation, or browser observation.
- Acceptance criteria: manifest and plan validate, JSONL request/notification
  response codec stores only metadata, initialize sends `initialize` and then
  `initialized`, duplicate initialize is blocked, and missing initialize
  response fails without raw data.
- Hard boundaries: no raw prompt, diff, path, body, token, cookie, session, MFA,
  browser storage, account credential, command payload, file payload, approval
  secret, raw schema, or raw JSONL transcript is persisted.
- Affected apps/packages: `packages/codex-app-server-adapter`, `tsconfig`,
  `tools/scaffold-health.ts`, docs.
- Risk level: high, because this introduces the App Server adapter package
  while deliberately keeping live process launch disabled.

## GStack Plan

- Plan: build a package shell with codec and in-memory lifecycle tests before
  real App Server calls.
- Build: add manifest, plan, JSONL encode/decode, in-memory transport, and
  initialize controller.
- Review: verify no raw transcript is returned in public summaries and no
  process boundary is invoked.
- QA: run focused adapter test/build/lint and foundation static audits.
- Ship: commit M54.3 independently before account/rate-limit reads.
- Retro: M54 can now model App Server initialize behavior without touching a
  real process.
