# M18.6 Remote Acceptance Smoke

## Scope

M18.6 validates the operator-facing remote GitHub chain after M18 without adding new execution capability. It covers doctor/readiness, approval metadata, branch publish rehearsal, publish-to-draft-PR rehearsal, governance projection, and Dashboard routes.

## Acceptance Matrix

| Check | Expected result | Boundary |
| --- | --- | --- |
| `codexhub doctor --json` | GitHub provider appears with configured target hashes and safe-enable blockers | Local metadata only |
| `codexhub approvals inbox --json` | Approval inbox is readable without a local-control token | Supervisor GET only |
| `codexhub approvals history --json` | Decision history is metadata-only | Local projection / GET only |
| `codexhub github branch-publishes rehearse --fixture --scenario all-pass --json` | Fixture rehearsal passes without network | No GitHub request |
| `codexhub github publish-draft-pr-chains rehearse --fixture --scenario all-pass --json` | Fixture chain passes without branch or PR creation | No GitHub request |
| `codexhub governance runs list --json` | Unified run projection remains readable | GET / projection only |
| Dashboard `#/github` | Shows GitHub readiness and remote chain summaries | Read-only |
| Dashboard `#/governance` | Shows run/evidence/audit projection | Read-only |
| Dashboard `#/readiness` | Shows operator blockers | Read-only |

## Observed Remote State

The configured local `origin` matches the expected GitHub target and is represented in operator output by target hashes only. Read-only remote connectivity succeeds and currently returns no heads, so remote publish and draft PR chains remain blocked until a governed remote bootstrap or existing base branch is available.

## Residual Risks

- M18 PR lifecycle status/check information is still projection-only; M19 adds the approval-gated live GET observation boundary.
- Empty repository bootstrap is intentionally not included. Creating the first remote ref must be a separate governed milestone.
- GitHub token readiness remains hash-only; the token is never stored in repo files or CLI arguments.

## Verification Evidence

- `pnpm nx run cli:test --skip-nx-cache`
- `pnpm nx run operator-readiness-kernel:test --skip-nx-cache`
- `pnpm scaffold:health`
- `pnpm audit:no-live-automation`
- `pnpm verify:foundation`

All M18.6 checks preserve the existing boundaries: no push, no branch creation, no PR creation, no raw token output, and no Dashboard/CLI write path.
