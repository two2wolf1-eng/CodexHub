# M57.5 App Server Stdio Boundary

Status: completed.

## GSD Spec

- Goal: add a governed Codex App Server stdio process boundary that can be used
  by later M57 dispatch only after preflight, approval, drift, and canary gates.
- Scope: `packages/codex-app-server-adapter`, focused adapter tests, and the
  no-live automation audit allowlist for the dedicated boundary file.
- Non-scope: no Supervisor POST integration, no real task dispatch from
  orchestrator, no event-driven task completion, no command/file approval
  auto-grant.
- Acceptance criteria: boundary blocks without required grants, starts only via
  fake spawner in tests when gates are ready, does not serialize the transport,
  and focused tests/build/lint plus static audits pass.
- Hard boundaries: no raw command, args, prompt, diff, path, body, token,
  cookie, session, MFA, storage, account identifier, approval secret, or
  process output body is stored in public results.
- Affected apps/packages: `packages/codex-app-server-adapter` and
  `tools/audit-no-live-automation.ts`.
- Risk level: high, because this introduces the audited external-process
  boundary for future live App Server dispatch.

## GStack Plan

- Plan: keep process launch in one audited boundary module.
- Build: add `createGovernedCodexAppServerStdioTransport` and a process-backed
  JSONL transport implementation.
- Review: confirm default manifest remains dry-run/no live dispatch while
  declaring the governed boundary is available.
- QA: run focused adapter tests/build/lint and static audits.
- Ship: commit M57.5 independently.
- Retro: M57.6 can now compose initialize/thread/turn/event lifecycle with this
  boundary.
