# M51.2 Unified Metadata Store

Status: completed.

## GSD Spec

- Goal: persist the M51 unified metadata contracts in `store-core` and
  `store-sqlite` so Supervisor can replace `missing-contracts-store`
  placeholders with real projections.
- Scope: `packages/store-core`, `packages/store-sqlite`, focused SQLite
  round-trip tests, scaffold health registration, release/review/runbook docs.
- Non-scope: no Supervisor route change, ChatGPT Business adapter, Chrome
  profile registry, browser automation, Codex App Server dispatch, account
  mutation, or live admin operation.
- Acceptance criteria: new async store interfaces exist; SQLite creates all M51
  metadata tables with the existing JSON payload pattern; round-trip tests prove
  metadata-only persistence and forbidden raw fields are rejected before storage.
- Hard boundaries: SQLite runtime remains isolated to `packages/store-sqlite`;
  `store-core` exposes async interfaces only; records store no raw prompt, diff,
  path, body, token, cookie, session, MFA, credential, or browser storage.
- Affected apps/packages: `packages/store-core`, `packages/store-sqlite`, docs,
  and `tools/scaffold-health.ts`.
- Risk level: critical, because persistence becomes the authority source for
  M51 Supervisor projections.

## GStack Plan

- Plan: add shared repository interfaces first, then SQLite tables and tests.
- Build: use the existing `id`, `recorded_at`, `payload` table shape.
- Review: confirm SQLite imports remain isolated and no route/adapter behavior
  changed.
- QA: run focused store builds/tests and foundation boundary audits.
- Ship: commit independently before M51.3 Supervisor projection work.
- Retro: Supervisor can now read metadata records without direct adapter calls.
